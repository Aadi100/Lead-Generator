# Lead Radar platform: module specs (read after app.md and UI-KIT.md)

Lead Radar is one complete professional platform: a real Dashboard home and separate modules, each its own route with a PageHeader, consistent patterns (skeleton -> data -> empty state), URL-synced filters, toasts for results, confirmations for destructive actions, keyboard access, light + dark, 1440 px and 390 px. All data comes from Supabase tables the app already uses (leads, outreach, replies, jobs, app_settings, suppressions, learning_events, deals, tasks). Keep ALL existing behaviour (enrich/draft/send jobs, realtime, settings logic); restructure and restyle only. Heavy aggregation is done client-side from limited selects (cap 2000 rows, use head+count queries for totals); never dangerouslySetInnerHTML; lead/reply text is plain text.

Route map and ownership (each fork edits only its own files; the shell, tokens and ui kit belong to the foundation and are read-only):
/ Dashboard | /leads Leads | /pipeline Pipeline | /outbox Outbox | /tasks Tasks | /contacts Contacts | /deals Deals | /trading, /trading/buyers, /trading/sellers, /trading/market, /trading/catalog Game Trading | /analytics Analytics | /activity Activity | /sources Sources | /capture Capture | /settings Settings | /help Help

## Dashboard  (/)
Greeting (profile.your_name or the signed-in email), date, quick actions (Capture, New task, New deal). Rows: (1) 7 StatTiles with 14-day sparklines: New leads (24 h), High-match leads (fit_score >= 70, status New), Drafts to review, Replies waiting (replies.handled=false), Open deals, Revenue this month (deals done, sum value), Profit this month (value - cost). (2) Two columns: "Today" (smart to-do: tasks due/overdue with check-off, drafts to review, unhandled replies, follow-ups due today from outreach.status='scheduled' and due_at <= end of day, top 5 hot new leads (fit >= 80), each with an Open button and a count header) and "Pipeline" (funnel New -> Pitched -> Replied -> Won with counts and conversion % as text + link). (3) Leads per day (30 days, services vs trading, accessible summary), Top sources (7 days, counts + avg trust bars), Source health (last lead time and 24 h count per source, amber/red when stale, link to /sources), Recent activity (10, link /activity), Game trading snapshot (buyers waiting, sellers found, matched, hot games; hide when trading is not enabled and show a "Set up trading" prompt), System status (worker, Claude CLI, sending paused, integrations that need keys), compact Setup progress until complete. Skeleton tiles while loading; each card has its own empty state.

## Leads  (/leads)  [services leads: lead_kind request and prospect; trade leads live under /trading]
As in app.md section 8 (master-detail list + right detail panel/drawer, KPI strip, sticky toolbar, status tabs with counts, bulk actions bar, keyboard shortcuts, list/cards toggle, realtime pulse, collapsible setup banner). Detail tabs: Overview, Company (enrichment), Messages (the DraftPanel flow), Notes & reminders (notes field + tasks for this lead with quick add) . Header actions: Create deal (-> /deals?new=1&lead=<id>), Add task, Open post, status buttons. Filters synced to the URL; selected lead in ?lead=<id> so links open the panel.

## Pipeline  (/pipeline)
Kanban over leads.status: New, Pitched, Replied, Won, Lost (+ a toggle to show Ignored). Column header with count and summed budget_amount; cards show title, source chip, category dot, fit + trust, budget (Fira Code), age, outreach state; scope filter All | Services | Trading, search, min fit slider. Drag and drop (HTML5 DnD with a visible drop target) AND a keyboard/mobile "Move to..." menu on every card. Moving to Won opens a small prompt to create a deal (value, optional); moving to Lost asks an optional reason (leads.outcome_note); updates are optimistic with rollback + toast. Click a card = side preview (title, flags, contact, notes) with "Open in Leads". Horizontal scroll with snap on mobile; columns collapsible.

## Outbox  (/outbox)
Tabs with counts: To review, Sending & scheduled, Sent, Replies (inbox), Problems. Desktop: list left, preview/editor right. Replies show category badge + summary + body expander, actions Mark handled / set lead Won or Lost / create task. Review & send reuses the DraftPanel behaviour. Clear primary buttons, safety warnings visible, daily-limit meter, paused banner.

## Tasks  (/tasks)
Table `tasks`. Quick-add bar ("Call Sam tomorrow", due shortcuts: today, tomorrow, in 3 days, next week, custom date), priority (low/normal/high), link to a lead or deal (searchable picker). Groups: Overdue, Today, Upcoming, No date, Done (collapsed). Checkbox with optimistic update and done_at, inline edit, delete with undo toast, filters (priority, linked), week strip showing counts per day. Lead detail and Dashboard show the same data.

## Contacts  (/contacts)
Directory built from enriched leads, grouped by website host, else company_name, else author. Row: company/person, website, owner + title, best email with status chip, phones, social icons, number of leads, last activity, outreach state. Search, filters (has email, verified email, source, status), sort, copy-email and export-CSV actions. Detail drawer: every field, all linked leads and their messages as a timeline, add task, create deal.

## Deals  (/deals)
Table `deals` (see supabase/schema-v4.sql). Toggle Table | Board by stage (talking, negotiating, agreed, paid, delivered, done, cancelled, disputed). KPI tiles: open value, won this month, revenue, profit, win rate, average deal. Charts: revenue and profit by month (last 6). Create/edit drawer: kind (service/trade), direction, title, company, contact, game and item type (trade), platform, value, cost, currency, stage, expected close, notes, linked lead (picker); closing sets closed_at; stage done + lead sets lead.status 'Won'; cancelled + lead sets 'Lost'. `?new=1&lead=<id>` opens the drawer prefilled from the lead. Filter by kind, export CSV.

## Game Trading  (/trading/*)   [leads where lead_kind = 'trade'; settings.trading, settings.trade_market, settings.trade_state, deals kind 'trade']
/trading Overview: KPI tiles (buyers waiting = trade_side buyer + status New + trade_match set, sellers found, matches, open trade deals, trade revenue and profit this month), Hot demand (game x item type from trade_market plus live counts: buyers, sellers, ratio, median price), New matches feed, weekly median price trend for the top games (SVG), suggestion cards ("what you can sell", from trading.suggestions) with Add to catalog, quick actions "Find trade leads now" (job trade_scan) and "Suggest what I can sell" (job suggest_trading) with progress, a setup status strip (trading enabled? catalog entries? sources?).
/trading/buyers: master-detail of buyer leads (people who want to buy what I sell): filters game, item type, price range, matched only, trust, status, source; sort best match; detail = post text, price, trade_match banner, trust + flags (scam signs highlighted), contact copy buttons, message draft (DraftPanel; channel manual: copy + open post + mark as sent), notes, Create deal, Add task.
/trading/sellers: same for sellers (suppliers): add a price-vs-limit indicator against the matching catalog entry (e.g. "18 % under your limit") and vs the market median.
/trading/market: demand vs supply by game and item type (paired bars with numbers), sortable table (buyers, sellers, ratio, median price), weekly median trend lines, suggestions list, data-coverage notes (sources used, days of data), "Refresh market" (suggest_trading).
/trading/catalog: What I sell and What I want as entry cards (label, game, item type, keywords, price limit, live count of matching leads) with add/edit drawer writing settings.trading (i_sell / i_want, set updated_at), master switch trading.enabled, extra games, extra subreddits (with the warning that a wrong name breaks the feed), and "Find leads now"; show trade_state.subs_ok. Settings > Trading becomes a pointer to this page (no duplicate editor).

## Analytics  (/analytics)   [replaces /insights]
Date range (7/30/90 days) in the URL. Funnel with conversion %, leads over time (area/bars), performance tables by source and category (leads, pitched, replied, won, win rate, avg trust, sortable), trust distribution, outreach stats (sent, replied, reply rate, by day), learning insights from settings.filter_learning + writing-rules summary with "Learn from my edits now" (job learn_writing) and "Refresh learning" (job learn_filters), trading market summary card linking to /trading/market, CSV export. Every chart has a text alternative.

## Activity  (/activity)
Unified feed (leads created, messages sent, replies received, deals created/closed, tasks completed) built from the tables' timestamps, grouped by day, filters by type, "Load more", each item links to its object (/leads?lead=, /outbox, /deals, /tasks). Exposes `useActivityFeed` from src/lib/activity.ts (written by the foundation) for the top-bar bell.

## Sources  (/sources)
One table of every lead source with health: name, kind (n8n scraper / worker / manual), schedule text, status chip (Healthy, Quiet, Needs key, Off, Problem), last lead found, leads in 24 h and 7 d, average trust. Derive from leads grouped by source and source_detail, settings.integrations.status, settings.trade_state, settings.prospecting, settings.worker_status. Row actions: Run now where a job exists (trade_scan, prospect_local, check_replies), Configure (links to Settings tabs / Trading catalog). A top card summarises automation health (worker online, Claude CLI, n8n sources fresh or stale, keys missing). n8n health: settings key `n8n_status` = {last_seen (ISO, written every 5 min by the Heartbeat workflow; older than 15 min = n8n offline), last_error:{workflow,node,message,at}, errors_total}; show it in the automation-health card and flag the failing workflow's sources. Known sources: Reddit hiring boards, Reddit business, Freelancer.com, Hacker News, We Work Remotely, Website form, OpenStreetMap prospects, Reddit trading, Google (Serper), X, Reddit API, Upwork inbox, Capture (manual).

## Help  (/help)
Searchable help: Getting started (6 steps with links), what each module does, glossary (trust score, fit score, enrichment, suppression list, capture bookmark), keyboard shortcuts table, FAQ (how to get alerts, why nothing is sent without approval, how replies are tracked, how to add API keys), safety rules, and an About card (worker status, Claude CLI, data counts).

## Settings  (/settings)
Grouped vertical tabs (top scroll strip on mobile): Profile & targeting (Profile & links, Targeting, Writing rules), Outreach (Email sending, Reply tracking, Safety), Sources (Connections, Alerts, Prospecting, Trading -> pointer to /trading/catalog), Appearance (theme Light/Dark/System, density Comfortable/Compact, default landing page), Data (export leads, outreach, deals and tasks as CSV; clear nothing destructive without confirmation). Sticky unsaved-changes bar, inline validation, secrets with show toggle, test buttons with inline result chips, status chips per integration. Existing tab components are restyled/regrouped, logic kept.

## Capture  (/capture)
Restyle only: numbered steps, draggable bookmark button, review list with sticky save bar, paste box, per-item outcomes.

## Cross-cutting acceptance
Every page: PageHeader, skeleton while loading, EmptyState with an action, error banner with Retry when a query fails, URL-synced filters, consistent chips/badges/status colours from the tokens, keyboard operable, focus visible, 44 px touch targets on mobile, no horizontal page scroll, no console errors (verify with the screenshot tool report), `npx tsc --noEmit` clean.
